# 连线质量与路由规范

这一页是 `drawio-skill` 的核心约束之一。绝大多数丑图和错图都不是因为“节点不会画”，而是因为连线处理失败。

## 1. 最高优先级原则

按优先级排序：

1. 连对
2. 看得懂
3. 不交叉
4. 不遮挡
5. 不啰嗦

不要为了“看起来整齐”而牺牲连接准确性。也不要为了“连接上了”就接受线条穿字、穿框、压标题。

## 2. 必须遵守的连线规则

### 2.1 连接必须有明确语义

每条线都应满足以下至少一项：

- 方向有意义
- 依赖关系有意义
- 数据流有意义
- 控制流有意义
- 所属关系或实现关系有意义

如果一条线只是“把两个东西连起来”，那通常说明图种选错了，或节点分组不对。

### 2.2 线条必须走通道，不要自由漂移

在开始布线前，先给画布留出“通道”：

- 主干通道
- 分支通道
- 回流通道
- 跨泳道通道

不要让每条边都临时找路。边应该共享少量稳定通道，而不是在节点缝隙中乱钻。

### 2.3 主流程边优先最短、最直、最显眼

主流程边：

- 拐点最少
- 视觉层级最高
- 不要绕远路

辅助说明边、异常边、依赖边可以稍弱，但不能抢走主流程注意力。

### 2.4 交叉是异常，不是默认

边线交叉只在这些情况下可以勉强接受：

- 图种本身结构极复杂，且拆页成本更高
- 交叉发生在视觉低密度区域
- 两条边都无法合理重排

即使如此，也应该先尝试：

- 调整节点位置
- 拆通道
- 改成多页
- 引入中间汇聚节点

### 2.5 线条不能穿过这些内容

- 文本标签
- 标题
- 图例
- 实体节点主体
- 关键图标主体

如果线必须进入容器，穿越容器外框可以接受；穿越普通节点主体通常不可接受。

### 2.6 边标签不能贴在线上

如果边带有标签，优先显式设置 offset，把标签推离边线。

否则常见后果是：

- 标签压在线上
- 标签压住节点边界
- 多条边在交汇区形成文字堆叠

## 3. 路由策略

## 3.1 架构图

- 优先左到右或上到下单向流
- 入口线、处理线、存储线分层
- 跨层连线尽量集中在边缘，不要穿越核心区域
- 外部系统与内部系统之间留出专门穿越带

## 3.2 流程图 / BPMN / 活动图

- 决策节点前后必须留出转向空间
- 分支线要在同一高度或同一宽度展开
- 汇合线回收时避免压住分支标签
- 跨泳道边集中从泳道空白区穿过

## 3.3 时序图

- 消息线基本保持水平
- 返回线与请求线风格不同
- `alt` / `loop` frame 内的线不要碰 frame 标题
- 激活框之间不要重叠

## 3.4 类图 / 组件图

- 实现、继承、依赖、组合的线型必须分清
- 接口点和端口应靠边放置，减少线进入组件主体
- 同一组件的多条出边要做扇出整理，不要堆在同一点附近

## 4. XML 层级与遮挡

draw.io 的 XML 顺序会影响显示层级。默认建议：

1. 页面背景与外层容器
2. 连线主干
3. 主节点
4. 注释、徽标、标签、装饰

一般来说：

- 线条应在节点下层
- 边标签应在边上层
- 说明文本应在大部分元素上层

如果出现“线盖住标题”或“节点被线切开”，先检查 XML 顺序，再检查布局。

## 5. 锚点与连接点

能明确指定就明确指定，不要让 draw.io 自行猜测连接点。

优先方式：

- 明确 `source` / `target`
- 必要时补 `sourcePoint` / `targetPoint`
- 对复杂边提供中间 `points`

避免：

- 多条线都吸附到节点中心附近
- 边从文本框中间穿出
- 不同语义的线争抢同一个连接点

如果目标节点本身是文本标签或信息框，优先用显式坐标，不要完全依赖自动连接。

## 6. 复杂图的拆解策略

如果你发现必须靠大量交叉才能画下，通常应该拆图，而不是继续补弯折：

- 总览图：只保留主路径
- 细节图：展开子流程
- 异常图：单独画失败/补偿路径
- 数据图：单独画读写流

复杂图的质量往往取决于“敢不敢拆页”，不是取决于“会不会多拐弯”。

## 7. 质量门禁

在 skill 执行中，以下流程应该成为默认动作：

1. 生成或修改图
2. 运行 `lint`
3. 修复 `edge_crossing`
4. 修复 `edge_through_node`
5. 修复明显 `node_overlap`
6. 再导出 PNG 目检

命令：

```bash
python scripts/drawio_tools.py lint path/to/file.drawio
```

如果还有 lint 告警，最终答复必须解释为什么保留。
