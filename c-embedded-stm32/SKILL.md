# STM32 嵌入式开发

## 核心目标

交付能直接放进用户现有 STM32CubeMX 工程、用户自己能继续修改的代码。先解决当前功能，再讨论可选的工程化增强。

## 用户代码风格

当 `D:/vscodeied/CDIO_AGV/CDIO_AGV/` 可读时，把其中应用层 `.c/.h` 文件作为首选风格参考。只学习表达方式，不照搬其中的旧错误或硬件参数。

- 使用简单、直接的函数，函数名能看出用途。
- 关键流程直接写出来，避免为了“架构完整”增加多层封装。
- 注释默认使用中文，重点说明函数功能、参数单位、硬件对应关系和修改位置。
- 优先沿用工程已有命名、缩进、头文件组织和 HAL 调用方式。
- 小型实验代码优先用普通变量和静态数组；没有实际并发需求时，不主动增加队列、互斥锁、DMA、环形缓冲区、二进制协议或 CRC。
- 任何默认数值都要说明来源。硬件参数未知时，让调用者传入或放在明显的宏中，不把猜测伪装成确定配置。
- 把“当前必须做”和“以后量产可增强”分开，不用量产级复杂度淹没实验代码。

## 工作流程

1. 读取当前工程的 `.ioc`、目标芯片、时钟树、外设句柄、引脚、RTOS 接口和编译器配置。
2. 只读取与任务直接相关的用户代码，确认用户现有写法和模块边界。
3. 明确输入、输出、单位、周期、范围和硬件通道映射。无法从工程确定的关键参数要明确标出。
4. 先给出最短可运行的数据流，再实现代码。
5. 只修改用户授权范围内的文件，保留 CubeMX 的 `USER CODE` 区域和现有改动。
6. 使用项目真实头文件或工具链做语法/构建检查；无法完整构建时，说明已验证到哪一层。
7. 删除验证过程中产生的临时目录和中间文件，保持工作目录整洁。

## 编码规则

### 通用规则

- 使用工程已有的 HAL 句柄，例如 `htim1`、`huart1`，不要另造一套外设对象。
- 头文件只公开调用者真正需要的宏、类型和函数。
- 优先使用定长整数类型；明确计数、毫秒、赫兹、CCR、转速等单位。
- 控制输出先做范围检查。电机、加热、功率输出启动前先写安全值。
- 不在中断中使用阻塞式串口、`printf`、动态内存或延时。
- 中断与任务共享的变量要按实际访问方式使用 `volatile`、临界区、队列或原子操作，不能只为“看起来安全”乱加关键字。
- 实验代码允许直接、简洁；发现会导致失控、越界、死锁或数据错误的问题时必须修正或明确警告。

### FreeRTOS

- 先沿用工程当前的 CMSIS-RTOS v1/v2 或原生 FreeRTOS 风格，不主动混搭接口。
- 周期任务优先使用 `vTaskDelayUntil()`，使采样周期不累加任务执行时间。
- 一个任务可以清楚完成的实验流程，不拆成多个任务和队列。
- 只有在发送会阻塞采样、数据确实可能丢失或多个执行单元共享资源时，才引入队列、DMA 或独立发送任务。
- 使用 `sprintf`、浮点格式化或较深 HAL 调用链时，提醒用户检查任务栈余量；给出栈大小时说明它是建议值，不冒充测量结果。

### STM32CubeMX 与定时器

- 先根据 APB 分频确认定时器实际时钟。APB 预分频不为 1 时，许多 STM32 系列的定时器时钟为对应 PCLK 的 2 倍。
- 边沿对齐 PWM 频率按 `f_pwm = f_tim / ((PSC + 1) * (ARR + 1))` 计算。
- PWM 频率需要固定时，保持 PSC 和 ARR 不变，只改变 CCR。占空比近似为 `CCR / (ARR + 1)`。
- 没有定时器同步需求时，主从模式、从模式和触发源保持禁用；不要为了“配置完整”随意开启。
- 编码器模式由 TI1/TI2 外部边沿计数，不使用普通内部时钟源。根据需要选择 TI12 四倍频、输入极性和数字滤波。
- 编码器输入是否上拉由输出电气类型决定：开漏输出或断线状态不确定时需要上拉；推挽输出通常不必内部上拉。优先依据编码器数据手册和板上电阻判断。
- 修改 CubeMX 生成文件时只写入 `USER CODE BEGIN/END` 区域，除非用户明确要求改生成配置文件。

### 电机、PWM 与编码器

- 先写清电机驱动真值表和通道映射，再设置 CCR。
- 双输入 H 桥单方向 PWM 常见写法是一个输入 PWM、另一个输入保持低；换向时交换两路。最终以驱动芯片数据手册为准。
- 两个电机同步实验应把同一个命令同时写入两个电机通道，但保留说明：机械安装或接线相反时需要交换某个电机的方向通道。
- 读取 16 位编码器计数时考虑回绕。若每周期读取后清零，说明允许的最大计数范围和可能丢失的极短读写窗口；若要求更严谨，再使用前后计数差。
- “计数/采样周期”本身就是离散速度量。只有知道四倍频后的每圈总计数时才换算 RPM：`rpm = delta * 60000 / (counts_per_rev * sample_ms)`。

## MATLAB 数据采集

用户要把实验数据放进 MATLAB 且未指定二进制协议时，默认输出 CSV 文本。

推荐表头：

```text
sample,time_ms,ccr,speed_a_count,speed_b_count
```

推荐数据行：

```text
0,10,1500,12,11
1,20,1500,13,12
```

- 第一行只发送一次表头，之后每个采样周期发送一行。
- 字段名保持简单稳定，让 MATLAB 可直接使用 `readtable()`。
- MCU 只需逐行发送，不要把整张表保存在 RAM 中。
- 发送前估算带宽：8N1 串口每字节约占 10 bit，`所需波特率 ≈ 每行字节数 × 每秒行数 × 10`，并留出余量。
- 只有文本带宽不足且用户接受解析脚本时，才改成二进制帧、CRC、DMA 或发送队列。

## M 序列实验

- 经典 M 序列是二值伪随机序列，所以必须有两个输入电平；这两个电平由工作点和激励幅值决定，不应随意写死。
- 用 `低电平 = 工作点 - 幅值`、`高电平 = 工作点 + 幅值` 表达选择依据，并限制在安全 CCR 范围内。
- ARR 决定 PWM 周期，M 序列应映射到 CCR，不要在辨识过程中改变 ARR 导致 PWM 频率变化。
- 每一位需要保持若干采样周期。保持时间要能激起电机动态，又不能长到实验效率很低；将它作为显式参数。
- 输出行里的 CCR 必须对应刚刚结束的那个采样区间，避免输入与速度错一拍。
- 序列数据逐行流向上位机。计算完整实验的行数、持续时间和串口数据量，明确 MCU RAM 不承担整表缓存。

## 审查与调试

- 用户只问原因时先诊断和解释，不未经授权改代码。
- 用户要求实现时，做范围内的最小修改并验证。
- 先查本地工程中的真实 HAL/CMSIS/FreeRTOS 声明；本地不足且事实可能变化时，再查 ST、ARM 或 FreeRTOS 官方资料。
- 报告问题时给出具体文件、位置、触发条件和影响。区分确定错误、当前可接受的简化、未来扩展风险。
- 对 HardFault、DMA、缓存、RTOS 竞态等问题先收集寄存器、调用路径、逻辑分析仪或任务栈数据，不凭印象定因。

## 完成标准

- 代码符合用户现有工程风格，中文注释清楚。
- 外设通道、方向、数值范围、单位和调用位置明确。
- 没有未经解释的“魔法参数”和不必要的复杂组件。
- 至少完成语法检查或真实工程构建检查，并说明限制。
- 临时文件已清理，最终目录只保留用户需要的文件。
