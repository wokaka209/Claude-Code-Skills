# 成品感与视觉打磨

这份参考用于吸收旧 `draw-io` skill 中真正有价值的“成品感”规则。

它关注的不是图是否“能用”，而是图是否已经达到：

- 文档级可读
- 幻灯片级可展示
- 技术文章级美观
- 不花哨但有完成度

## 1. 核心原则

- 先保证结构正确，再做视觉打磨
- 打磨的目标是更清晰，不是更热闹
- 如果一个视觉元素不能提升理解，就应考虑删掉

## 2. 字体与排版默认值

### 2.1 始终显式指定字体

如果图里有较多文本，优先在 `mxGraphModel` 上设置 `defaultFontFamily`，并尽量在文字节点上明确写 `fontFamily`。

示例：

```xml
<mxGraphModel defaultFontFamily="Noto Sans" ...>
```

```xml
style="text;html=1;fontSize=16;fontFamily=Noto Sans;"
```

### 2.2 按运行环境选择更稳妥的字体

如果是导出预览或本地定稿，可以按平台选字体：

| 平台 | 中文优先 | 英文/通用优先 |
|------|----------|---------------|
| macOS | `PingFang SC` | `Helvetica Neue` |
| Windows | `Microsoft YaHei` | `Segoe UI` |
| Linux | `Noto Sans CJK SC` | `Noto Sans` |
| 跨平台共享 | `Noto Sans` | `Noto Sans` |

如果图会跨平台流转，优先选择 `Noto Sans` 或 `Noto Sans CJK` 这类更稳定的字体族。

### 2.3 字号不要吝啬

旧 `draw-io` skill 的一个优点是它默认更偏“可读”，不是过小。

建议：

- 页面标题：20 到 28
- 容器标题：16 到 22
- 普通节点：13 到 16
- 注释：11 到 13

如果图面拥挤，优先加留白，不要先把字缩小。

### 2.4 中日韩文本宽度要预留

对 CJK 文本，不要按英文宽度估算。

经验值：

- 30 到 40 px / 字，适合标题或标签
- 24 到 32 px / 字，适合普通节点正文

如果文本自然会换行，应主动用 `&lt;br&gt;` 控制，而不是让它随机折行。

## 3. 背景、边框与对比

### 3.1 背景默认透明

如果不是明确需要海报风或深色成图，优先保持透明背景，不要硬设：

```xml
background="#ffffff"
```

透明背景更适合：

- 文档嵌入
- 幻灯片
- 多主题页面

### 3.2 容器边框比填充更重要

容器的存在感，优先靠：

- 清晰边框
- 合理圆角
- 明确标题带
- 适度内边距

不要靠大面积重色填充去“强行显眼”。

## 4. 箭头与连线的成品感

### 4.1 箭头放在后层

旧 `draw-io` skill 的一个好规则是：边线尽量放在节点后层。

在 XML 顺序上通常建议：

1. 标题
2. 主连线
3. 容器与节点
4. 标签与注释

这样可以减少“线切开节点主体”的视觉噪音。

### 4.2 边标签要主动偏移

边标签不要默认压在线上。

示例：

```xml
<mxPoint x="0" y="-24" as="offset"/>
```

或：

```xml
<mxPoint x="0" y="24" as="offset"/>
```

原则：

- 上方标签用负 y
- 下方标签用正 y
- 离边至少 16 到 32 px

### 4.3 文本节点附近的连线要显式定点

如果边连到文字节点、标签节点或复杂图标附近，不要完全依赖自动吸附。

优先补：

- `sourcePoint`
- `targetPoint`
- `Array as="points"`

这样比“让边自动找出口”更稳，也更不容易压字。

## 5. 容器与内部元素

### 5.1 容器内边距至少 30 px

尤其适用于：

- VPC / 子网 / 安全组
- 卡片式分组框
- 泳道
- 信息图层级框

30 px 是较稳妥的最低值。对大容器可以到 40 px。

### 5.2 标题不要贴边

容器标题应：

- 距上边 20 到 32 px
- 距左边 16 到 30 px

如果标题太靠边，整张图会显得廉价和拥挤。

## 6. 文案与标签收敛

### 6.1 标题尽量短

- 服务名单独一行时就不要加解释
- 有补充信息时再用第二行
- 冗余词要删掉

例如：

- 用 `Amazon ECR`
- 不用 `Amazon ECR Container Registry`

### 6.2 一图只保留必要装饰

旧 `draw-io` skill 的另一个优点是会删掉无必要图标。

例子：

- 已经有 `Amazon ECR` 图标，就不必再放一个 Docker 图标
- 已经有清晰标题，就不需要额外 decorative badge

## 7. 多页图的完成度

如果是多页图，不仅要逻辑一致，还要“像一个系列”：

- 标题体系一致
- 字体体系一致
- 色彩关系一致
- 注释块风格一致
- 留白节奏一致

## 8. 复杂系统要分层表达

旧 `draw-io` skill 在“分阶段图”这点上是对的。

复杂图优先拆成：

- Context Diagram
- System Diagram
- Component Diagram
- Deployment Diagram
- Data Flow Diagram
- Sequence Diagram

不要试图把所有层次塞进一页。

## 9. 打磨清单

导出前，至少再问自己这几个问题：

- 文字够大吗
- 背景是否透明
- 边标签是否离线足够远
- 箭头是否在后层
- 标题是否贴边
- 是否存在无意义装饰
- 是否删掉了重复图标或重复说明
- 这一页像不像已经可以放进文档或文章
