# 视觉系统与去同质化规范

很多 AI 生成的图会陷入同一种"默认企业蓝 + 默认圆角框 + 默认细线 + 平庸布局"的风格。这个 skill 不应该这么做。

新建图时，应当先有意识地选择一个视觉系统。除非用户已经有现成设计语言，否则不要无意识使用同一种样式。

## 1. 什么时候必须考虑风格

以下情况不能只求"能看"：

- 汇报用架构图
- 方案评审图
- 高层概览图
- 对外文档图
- 多页系列图

## 2. 风格选择原则

风格应服从内容：

- 基础设施与架构：稳定、理性、分层清晰
- 业务流程：方向感强、节奏清晰
- UML：克制、结构化、符号优先
- 时间线：节奏和层次比图标更重要
- 思维导图：枝干感、层级感

## 3. 推荐视觉系统

### 3.1 Blueprint
适用：AWS 架构图、部署图、数据流图
特征：冷色系、清晰分层、边框略强、线条较克制

### 3.2 Operations Board
适用：流程图、BPMN、工作流
特征：强方向感、主流程高对比、决策节点清晰

### 3.3 Editorial Minimal
适用：UML、组件图、类图
特征：极少颜色、依靠线型/留白/层级表达

### 3.4 Analytical Contrast
适用：威胁建模、鱼骨图、因果图
特征：重点路径突出、异常/风险用对比色

### 3.5 Product Narrative
适用：时间线、路线图、管理层概览
特征：版式感更强、节点更像卡片、留白更多

## 4. 去同质化手段

至少从这些维度里主动选 2 到 3 个做区分：

- 容器形状体系
- 线条粗细与边角风格
- 配色关系
- 标题与正文层级
- 图例位置
- 注释块风格

## 5. 不要这样做

- 所有图都用一套默认淡蓝色矩形
- 所有节点都统一圆角，完全不区分类别
- 颜色很多，但没有语义
- 图标很多，但没有层次
- 依赖粗线条"热闹感"掩盖结构不清
